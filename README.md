# texkit-swiftlatex

Deterministic build chain for the TeXKit (Obsidian plugin) pdfTeX WASM
engine. From pinned upstream sources it produces four release assets —
`swiftlatexpdftex.worker.js`, `swiftlatexpdftex.fmt`, `pdftocairo.js`
(wasm-opt stripped) and `texfiles.tar.gz` — verifies them against size
and determinism gates, and publishes them as a GitHub release (`engine-vN`)
together with a sha256+bytes manifest.

## Build

Prerequisites: a TeX Live 2025 install (default `~/texlive/2025`) and emsdk
6.0.8. Resolution overrides where a script needs one: `KPSEWHICH` (closure
derive/materialize), `FMT_KPSE` (fmt build), `TEXMF_DIST` (closure derive),
`TEXLIVE_ROOT` (license audit). All commands run from the repo root.

```sh
scripts/fetch-sources.sh        # materialize the pinned upstream trees into src/
bash scripts/build-worker.sh      # build/swiftlatexpdftex.worker.js (+ node twin)
bash scripts/build-fmt.sh         # build/swiftlatexpdftex.fmt (self double-build gate)
bash scripts/build-pdftocairo.sh  # build/out/pdftocairo.stripped.js (release name: pdftocairo.js)
python3 scripts/derive-closure.py   # closure/closure-list.txt (committed snapshot, 619 names)
python3 scripts/materialize-closure.py && sh scripts/pack-closure.sh  # build/texfiles.tar.gz
bash scripts/make-manifest.sh     # build/engine-manifest.json (release attachment)
```

`scripts/publish.sh --yes` uploads the four assets plus manifest and notices
to the `engine-vN` release. It is manual-only by design.

## CI

Two workflows run on every push and pull request
(`.github/workflows/`), both secret-free with zero permissions:

- **static-guard** — script syntax plus `tests/privacy-gate.sh`: shape-based
  scans for machine-identity paths, credential shapes, and non-English
  tracked text, the never-tracked AI/personal state file guard, and a
  guard that the tracked `.gitignore` stays neutral (no workflow-shape
  disclosure).
- **closure-repro** — rebuilds the closure tarball inside a digest-pinned
  frozen TeX Live 2025 image and byte-compares it against the recorded
  baseline for that image. A foreign machine reproducing the tarball
  byte-identically is the structural proof that no build-machine identity
  is embedded (same-machine rebuilds cannot prove this). The materialize
  step also runs the machine-identity leak gate with the runner's own
  identity as needles, and the delta against the engine-v1 release asset
  (one updmap-generated member) is reported every run — see
  `docs/determinism.md`, "CI closure reproduction".

## Mirror policy

This repository is a read-only public mirror of a private development
tree: every release drop rebuilds it from that tree as a single commit
and force-updates `main` (flat history by design; the `engine-vN` tags
are the stable anchors). The model:

- Issues are welcome; patches as issue proposals; pull requests are not
  accepted — the mirror base is regenerated by design.
- Public updates follow release drops — quietness between releases is
  the model, not abandonment.
- Forks inherit living gates: both CI workflows re-run the in-repo
  verification on every push.

## Gates

- **Corpus gate** — `node tests/corpus-gate.mjs`: 27 probe figures
  (byte-shipped corpus vs. TL2025 reference), error-path compile, warm-worker
  recompile scenario and the size budget. Authoritative record:
  `docs/corpus-gate.md`.
- **Determinism gate** — same-source double run must be byte-identical for
  all four assets before a release. Records and expected hashes:
  `docs/determinism.md`.
- **Size** — the four assets together must stay ≤ 50 MiB.
- **Strip** — `pdftocairo.js` is built with `wasm-opt --strip-debug
  --strip-producers`; SVG output must be byte-identical before/after strip.

## Upstream pins

Single source of truth: `toolchain.lock.json`.
Upstream trees live in `src/` (gitignored — re-fetched, never versioned);
the one carried patch is `patches/0001-pdftex-harness-kpse-protocol.patch`.
License attribution for everything that ships: `THIRD-PARTY-NOTICES.md`.

## Layout

| Path | Purpose |
|---|---|
| `scripts/` | build / gate / publish entry points (shell, node, python) |
| `tests/` | corpus gate + smoke drivers, gate corpus, frozen probe corpus, spike harness |
| `closure/` | committed closure name-list snapshot (byte-identity gate target) |
| `docs/` | verification records (determinism, gate, comparisons, decisions) |
| `patches/` | the one carried SwiftLaTeX patch |
| `build/` | generated outputs only (gitignored) — assets, staging, scratch |
