# Font directories mirrored WHOLESALE into the closure, bypassing corpus
# trimming — font size selection is driven unpredictably by user documents
# (sub/superscripts -> script sizes; a missing .pfb aborts the engine while
# a missing .tfm is only a recoverable TeX error, so PFB and TFM trees are
# BOTH required). Glyph shape is equally user-driven: a .vf-backed .tfm
# whose .vf is missing aborts at shipout (vf names carry no map entry), so
# the vf tree is staged alongside.
# One TL2025 texmf-dist directory per line; every *.pfb / *.tfm / *.vf
# directly inside it is staged (flat basenames, closure-list spelling).
#
# cm family (kpsewhich-verified 2026-09-03): .pfb in type1/public/amsfonts/cm
# (75 — the dir's 150 entries are 75 pfb + 75 .pfm pairs; .pfm is
# Windows-only metrics, not staged); .tfm split across tfm/public/cm (75)
# and tfm/public/amsfonts/cmextra (15) — tfm/public/amsfonts/cm does NOT
# exist.
#
# Common math alphabets (user-directed extension, same date): rsfs =
# \mathscr via mathrsfs (3 tfm + 3 pfb); amsfonts/symbols = msam/msbm,
# \mathbb & AMS symbols via amssymb (12 + 12); amsfonts/euler = eufm/eusb/
# euscript/euex/eurb, \mathfrak & Euler faces via eufrak/euscript
# (40 tfm + 22 pfb). Their .sty/.fd macro layer is already in the closure
# (amssymb/amsfonts/amsbsy/eufrak/euscript/mathrsfs.sty + ursfs.fd), and
# rsfs + amsfonts font families are already in the audited release.
# bbm is deliberately EXCLUDED: a separate license family needing a new
# audit, and \mathbb via amssymb/msbm covers the common need.

# slots) ships through VIRTUAL fonts. A corpus-derived closure carries
